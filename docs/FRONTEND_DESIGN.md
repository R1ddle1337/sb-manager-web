# WebUI 前端设计说明

## 目标

WebUI 借鉴 [Cli-Proxy-API-Management-Center](https://github.com/router-for-me/Cli-Proxy-API-Management-Center) 的信息架构和运维工作台体验，但不复制其源码、Logo、图标文件或品牌资源。页面继续使用 Go `embed` 打包，部署时不依赖 CDN 和 Node.js。

设计重点是让第一次使用 `sb-manager` 的用户按真实操作顺序完成“看状态、选目标、做操作、看结果”四件事：

1. 首屏显示服务、节点、BBR 和 HY2 UDP 缓冲区四项关键指标。
2. 常用变更使用快捷操作卡片触发固定任务，结果进入任务审计区。
3. 总览、服务器、节点、任务和系统维护是互斥工作区，左侧导航切换内容，不再依赖超长页面锚点。
4. 页面展示的是脚本状态和任务结果，不直接编辑生成的 sing-box `config.json`。

## 信息架构

```text
侧栏
├── 总览（关键状态、常用操作、下一步引导）
├── 服务器（清单、版本、批量任务）
├── 节点与用户（节点 CRUD、分享、用户）
├── 任务记录（结果、取消、重试）
├── 系统维护（WebUI、Realm、证书、密码）
├── 高级运维
└── 账号与安全

顶栏
├── 面包屑和当前工作区
├── 本机连接状态
├── 刷新
└── 退出登录

节点创建使用按需弹窗：基础字段始终显示，协议高级项按当前协议动态展示。
原始 JSON 收进可展开区域，不再占据默认主视觉。批量操作固定展示目标、动作和
灰度策略，并在提交前执行 preflight。
```

表格中的服务器和节点名称链接到 `/servers/{id}` 及
`/servers/{id}/nodes/{node}` 详情页。详情页提供能力快照和节点编辑表单，
首次使用仍从总览开始，不要求用户理解 URL 结构。

## 视觉规范

- 使用浅灰工作区、白色实体面板和稳定的左侧导航，避免悬停展开和玻璃拟态造成的定位漂移。
- 蓝色代表控制动作，绿色代表成功/在线，琥珀色代表需要注意，红色只用于失败或危险操作。
- KPI 使用四种强调色，但正文保持统一的高对比度灰白色，避免彩色文字影响阅读。
- 表格提供横向滚动，操作按钮使用紧凑尺寸，长输出放入可滚动的等宽代码块。
- 所有动作仍是固定 API action，不在浏览器提供任意命令输入框。

## 响应式行为

- 桌面端（>760px）：固定展开的左侧导航，内容区使用 KPI 网格和双栏工作台。
- 中等宽度（≤1080px）：KPI 变为两列，状态和快捷操作变为上下排列。
- 移动端（≤760px）：导航折叠为抽屉，KPI 保持两列；表单变为单列，表格保留横向滚动。
- 导航点击后自动关闭移动端抽屉，并更新顶栏当前工作区名称。

## 可访问性与安全边界

- 导航、刷新、菜单和表单按钮带有可读文本或 `aria-label`。
- 动态告警使用 `aria-live="polite"`；用户输入和 API 内容进入 DOM 前统一 HTML 转义。
- 页面继续依赖既有登录、Session、CSRF 和固定 action 白名单；视觉重构不会改变权限模型。
- 节点密码、证书私钥、Snell PSK 和 Realm token 不在前端持久化，也不会写入控制端 SQLite。

## 当前交付状态

上述工作区能力均已落地：任务表支持状态筛选和详情抽屉，节点编辑和
服务器详情页独立可访问，批量任务显示完成/失败计数，协议高级字段会
根据核心版本提示兼容性；顶栏提供浅色主题和 30/60 秒自动刷新选项。
